# VoluFormer3D V9 — Tier B Design Spec

**Date**: 2026-04-20
**Status**: Approved, implementation starting
**Target**: AMOS22 CT Dice **0.85-0.88** (SOTA-match), beating MCP-MedSAM 0.79-0.82

---

## 1. Motivation

V7 3D Dice = 0.362 on AMOS22 val (20 vols). V7's 2D-slab-only OrganFlowSAM2
architecture has a ceiling ~0.70-0.78 because:

- Training sees only organ-present slabs → 3D inference on absent-organ slabs
  produces hallucinated positives.
- 2D-slab decoder has no true 3D context; ODE partially mitigates but can't
  match native 3D receptive fields.
- Small organs (esophagus, bladder, pancreas) need 3D shape priors and global
  Z-axis context that 8-slice windows can't provide.

To hit SOTA-tier (0.85+) we need a native 3D model at the core. But we don't
want to throw away OrganFlowSAM2 — its ODE, anatomy graph decoder, LoRA MedSAM2
encoder, and cross-slice flow loss are all contributions worth preserving.

## 2. Architecture: Cascade 3D-proposer → 2D-slab-refiner

**Stage 1 (proposer)**: `SwinUNETR-3D` consumes the full isotropic volume at
`(96, 96, 96)` patches with 50% overlap, produces a coarse 15-organ 3D
probability map.

**Stage 2 (refiner)**: `OrganFlowSAM2` takes the proposal + the image and emits
a fine-res per-slice mask. The proposer's mask is used:
  (a) to sample training slabs around true organ regions,
  (b) as a gating prior on the refiner's output — regions where the proposer
      is confident empty get zeroed, eliminating V7's false-positive problem.

**Stage 3 (ensemble)**: At inference, we combine proposer + refiner outputs
via a learned fusion gate (`AnatomicalCascadeFusion`).

```
            CT Volume
                │
       [SwinUNETR-3D + Teacher Distill]     Novel #3
                │
      Coarse 3D proposal (15, Z, H, W)
                │   ├─── Stage 1 loss (Dice + CE on 3D)
                │
       ROI + slab sampler
                │
       Slab (D=8, 3, 320, 320)
                │
   [OrganFlowSAM2 + Mamba-ODE + Dynamic PFESA]  Novel #2, #6
                │   ├── Cross-modal InfoNCE     Novel #4
                │   ├── Flow shape prior        Novel #5
                │   └── Cascade consistency     Novel #7
                │
         Refined 2D mask
                │
       [Boundary DDPM refiner]               Novel #8
                │
       Fine-res mask (high-uncertainty regions refined)
                │
       AnatomicalCascadeFusion(prop, ref)    Novel #1
                │
         Final 3D mask
```

## 3. Eight Novel Contributions

| # | Name | Module | Novelty claim |
|---|------|--------|---------------|
| 1 | **Anatomical cascade fusion** | `models/voluformer_v9.py` | Learned gating between 3D proposer and 2D-slab refiner. No prior work combines a 3D U-Net proposer with a SAM2-LoRA 2D refiner for multi-organ; cascade fusion is learned, not heuristic. |
| 2 | **Mamba-ODE hybrid cross-slice** | `models/mamba_ode.py` | Flow-matched ODE handles local smooth cross-slice continuity; a selective-scan Mamba block handles long-range Z dependencies. First hybrid ODE+SSM for medical 3D. |
| 3 | **Teacher-ensemble distillation** | `losses/teacher_distill.py` | SAM2 + DINOv2 + BiomedCLIP features distilled into SwinUNETR backbone via multi-teacher feature matching + adaptive per-organ teacher weighting. |
| 4 | **Cross-modal InfoNCE alignment** | `losses/cross_modal_contrastive.py` | InfoNCE between per-organ pooled image features and BiomedCLIP text embeddings, with hard-negative mining across organs. |
| 5 | **Flow-matched shape prior** | `losses/flow_shape_prior.py` | Extend our existing ODE to also generate organ shape priors conditioned on organ_id; regularize predicted mask toward generated prior. |
| 6 | **Organ-aware dynamic PFESA++** | `models/dynamic_pfesa.py` | PFESA kernel weights generated by a HyperNetwork from `organ_id` + text embedding. No prior work makes PFESA kernels organ-conditioned. |
| 7 | **Cascade consistency loss** | `losses/cascade_consistency.py` | KL + soft-Dice between SwinUNETR proposal and OrganFlowSAM2 refined mask in overlap regions. Prevents refiner drift from proposer's 3D context. |
| 8 | **Boundary-aware DDPM refiner** | `models/boundary_ddpm.py` | A tiny (3 M) DDPM head runs 10 denoising steps ONLY on predicted mask boundaries (high-uncertainty band). Modernizes MedSegDiff for thin-organ boundaries. |

## 4. Data Strategy

Training volumes:
- **AMOS22 CT train**: 200 (already owned)
- **FLARE22 CT**: 500 (download Phase 2, 30 GB)
- **TotalSegmentator pseudo-labels**: ~1204 CTs (run TotalSegmentator on
  public unlabeled CT, map 104 structures → AMOS22 15-organ schema)

Total: ~1900 CTs → ~10× V7's effective training data.

Sampling strategy (V9 dataset):
- 50% positive slabs (organ present) — matches V7
- 30% negative slabs (organ absent) — NEW, fixes distribution shift
- 20% mixed slabs (multiple organs present) — NEW, reinforces multi-organ co-occurrence

## 5. Training Schedule

**Stage 1** — SwinUNETR-3D proposer alone (AMOS22 + FLARE22 + pseudo-labels)
  - 50 ep, 4× patch per batch, AdamW 3e-4
  - Target stage-1 Dice: 0.75-0.80 (3D only)

**Stage 2** — Freeze proposer, train OrganFlowSAM2 refiner
  - 40 ep, slab-conditioned on proposer ROI
  - All 8 novel losses ON
  - Target stage-2 3D Dice: 0.82-0.86

**Stage 3** — Joint fine-tune (proposer + refiner + fusion)
  - 15 ep, low lr 5e-5
  - Cascade consistency weighted up
  - Target stage-3 3D Dice: 0.85-0.88

GPU time estimate: Stage 1 ~30 h, Stage 2 ~40 h, Stage 3 ~15 h → ~85 h total.

## 6. Eval

`evaluation/eval_v9_3d.py`:
- Resample volume to 1.5×1.5×1.5 mm isotropic
- 96³ sliding window, 50% overlap, Gaussian blend
- 8-way TTA (flip x3 + rot90 x4)
- Connected-component + hole-fill postproc
- Report: per-organ 3D Dice, HD95, NSD, mean Dice

## 7b. Loss-preservation clause (safety net)

Stage 2 refiner loss = **V7's working stack** (Dice + Tversky on center-slice,
light deepsup, light ds_scale, XSC 0.25, flow 0.5) **PLUS** the five new
training losses (teacher distill, cross-modal InfoNCE, flow shape prior,
cascade consistency, boundary DDPM). All new loss weights default to λ = 0 in
`configs/v9_tierB.yaml` — so the first training run can set one λ at a time
nonzero for ablation, and "all novelties off" recovers V7's exact loss surface.
This is the explicit guardrail against V6's "turned everything on, everything
collapsed" failure.

## 7c. Mandatory checks before any full training run

Every stage launch is gated by:
1. `tests/v9_cuda_smoke.py` passes on the 4090 with `peak VRAM < 22 GB`.
2. Warm-start loader prints missing/unexpected keys; abort if >10 % of keys
   from the source checkpoint are missing.
3. Training script has stop-rule (`abort if val/dice_3d < best - 0.02` on two
   consecutive val ticks) and per-component loss logging active.

## 8. Guardrails (from feedback memory)

- **One-axis-at-a-time**: Each stage changes one subsystem.
  Stage 1 = proposer alone. Stage 2 = refiner + novel losses on a frozen
  proposer. Stage 3 = joint only after 1+2 validated.
- **3D eval is source of truth**: No SOTA claim from 2D slice Dice.
- **Stop-rule**: If Stage 1 doesn't hit 0.70 by ep25, diagnose before continuing.
- **Smoke test CUDA**: every new module + combined pipeline before any full run.
- **Fresh checkpoint dirs**: `checkpoints/v9_stage1/`, `checkpoints/v9_stage2/`,
  `checkpoints/v9_stage3/`. Never rename in place.
- **Ablation plan (pre-committed)**: Once V9 beats 0.80 3D, run single-seed ablations:
  V9-no-cascade, V9-no-mamba, V9-no-distill, V9-no-infonce, V9-no-ddpm.
